### Summary of Lecture Material: Modeling Process & Algorithms in Machine Learning

#### Introduction
- **Context**: 
  - Situating machine learning in real-world applications.
  - Emphasizing the broader process beyond just running algorithms.
  
- **What We Will Learn**:
  - Best practices in the modeling process.
  - Key aspects of modeling, evaluation, and interpretation.
  - Overview of key algorithms and their strengths and limitations.
  - Applying machine learning to real-world structured data.

#### Modeling Process
- **Best Practices**:
  - Problem identification and framing.
  - Data collection and feature selection.
  - Algorithm selection considering performance, interpretability, and computational cost.
  - Importance of simplicity (Occam's Razor).
  - Avoiding data leakage and ensuring proper validation.
  - Balancing bias and variance.
  - Evaluating models using appropriate metrics and cross-validation.

- **Algorithm Selection**:
  - No Free Lunch Theorem: No single algorithm universally outperforms others.
  - Trade-offs between performance, interpretability, and computational cost.
  - Occam's Razor: Prefer simpler solutions when other factors are equal.
  - Example: Choosing between a complex model and a simpler one for practicality.

- **Model Evaluation**:
  - Train-test split to avoid overfitting.
  - Proper use of validation sets and cross-validation.
  - Importance of avoiding tuning on the test set.
  - Sampling strategies: Random vs. non-probability, stratified, weighted.
  - Identifying and mitigating data leakage.
  - Understanding the bias-variance tradeoff.
  - Plotting validation curves to diagnose overfitting.

- **Metrics**:
  - Distinguishing between outcomes (business goals) and outputs (model performance metrics).
  - Regression metrics: Mean Squared Error (MSE), Mean Absolute Error (MAE), Mean Absolute Percentage Error (MAPE), R².
  - Classification metrics: Accuracy, Precision, Recall, False Positive Rate (FPR), Area Under ROC Curve (AUROC), Precision-Recall curve.

- **Feature Selection**:
  - Removing high-null features and reducing multicollinearity.
  - Using feature selection methods like `SelectKBest` and Random Forest importance.
  - Manual inspection of selected features.
  - Encoding techniques: Ordinal and one-hot encoding.
  - Scaling for algorithms requiring it (e.g., KNN, clustering, regularized regression).

- **Class Imbalance**:
  - Addressing class imbalance to avoid accuracy traps.
  - Techniques: Oversampling, undersampling.
  - Fixing root causes whenever possible.

- **Pipelines**:
  - Preventing data leakage.
  - Ensuring reproducibility.
  - Cleaner production workflows.

#### Supervised vs. Unsupervised Learning
- **Supervised Learning**:
  - Known inputs (features) and outputs (targets).
  - Types: Regression (predicting numeric values) and Classification (predicting categories).
  - Examples: Stock price prediction (regression), fake news detection (classification).

- **Unsupervised Learning**:
  - Only known inputs (features).
  - Goal: Logical organization of input data.

#### Heuristics vs. Machine Learning
- **Heuristics**:
  - Simple rules based on past experience.
  - Example: Demand prediction using current day temperature.
  - Value in providing a starting point and baseline performance.

- **Machine Learning**:
  - More adaptable and scalable compared to heuristics.
  - Example: Weather forecasting using historical data and weather patterns.

#### Practical Application

- **Baseline Development**:
  - Starting with simple heuristics and machine learning algorithms (linear regression, logistic regression).
  - Improving upon baselines through more complex models.

- **Algorithm Selection**:
  - Consideration of performance, interpretability, and computational cost.
  - Example: Choosing between a linear regression and a neural network for a specific task.

- **Evaluation Metrics**:
  - Importance of setting outcomes (business goals) before evaluating models.
  - Differentiating between regression and classification tasks.

- **Feature Engineering**:
  - Removing high-null features and reducing multicollinearity.
  - Using feature selection methods like `SelectKBest` and Random Forest importance.
  - Manual inspection of selected features.

- **Handling Class Imbalance**:
  - Addressing class imbalance to ensure accurate model performance.

- **Pipelines**:
  - Preventing data leakage and ensuring reproducibility.

### Detailed Explanation of Sampling Methods

#### Non-Probability Sampling
- **Definition**: Sampling where the selection of data is not based on any probability criteria.
- **Types**:
  - **Convenience Sampling**: Selecting data based on ease of access. For example, using Google Images for flower pictures.
  - **Snowball Sampling**: Recruit participants through referrals from initial respondents. For instance, scraping Twitter accounts based on users followed by initial users.
  - **Judgment Sampling**: Selecting data based on expert judgment. An example could be selecting survey respondents based on age groups.
  - **Quota Sampling**: Setting quotas for subgroups to ensure representation. For example, collecting 100 responses from each age group.

#### Random Sampling
- **Definition**: Selecting data randomly to ensure each element has an equal chance of being included.
- **Types**:
  - **Simple Random Sampling**: Every element in the population has an equal chance of being selected. For example, randomly picking 100 students from a list of 1000.
  - **Stratified Sampling**: Dividing the population into strata (subgroups) and then randomly sampling from each stratum. Useful when dealing with imbalanced data. For example, dividing customers by income levels and then sampling from each group.
  - **Weighted Sampling**: Assigning weights to elements to reflect their importance or likelihood of occurrence. For example, weighting recent data higher in a time-series analysis.

#### Purpose of Sampling
- **Non-Probability Sampling**: Often used when the population is large and complete enumeration is impractical. It can be quicker and easier but introduces bias.
- **Random Sampling**: Used to reduce bias and ensure that the sample is representative of the population. It provides a more reliable estimate of the population parameters.

#### Examples of When to Use Each Type of Sampling
- **Convenience Sampling**: Suitable for preliminary exploratory studies or when resources are limited. For example, conducting a quick survey on social media platforms.
- **Snowball Sampling**: Effective when studying hard-to-reach populations, such as underground communities or niche markets. For example, recruiting participants for a study on cryptocurrency usage.
- **Judgment Sampling**: Useful when expert opinion is crucial, such as in qualitative research or when dealing with subjective data. For example, selecting judges for a legal study.
- **Quota Sampling**: Ideal when you need to ensure representation from specific subgroups. For example, ensuring diversity in a focus group by setting quotas for different demographic groups.
- **Simple Random Sampling**: Best for obtaining a representative sample when the population is homogeneous. For example, selecting a random sample of employees for a health screening.
- **Stratified Sampling**: Necessary when the population is heterogeneous and you want to ensure representation from all subgroups. For example, stratifying a population by age and gender to ensure balanced representation in a study.
- **Weighted Sampling**: Essential when dealing with imbalanced data or when certain subsets of the population are more important. For example, weighting recent data higher in a time-series analysis to account for recent trends.

### Practical Tips for Sampling
- **Ensure Representativeness**: Use random sampling to avoid bias.
- **Address Imbalances**: Use stratified or weighted sampling to address imbalances in the population.
- **Consider Resources**: Use convenience sampling when resources are limited but acknowledge the potential for bias.
- **Validate Results**: Always validate the results of your sampling method to ensure reliability.
