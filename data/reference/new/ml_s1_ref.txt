## 1. Machine Learning in Context: “Machine Learning That Matters”

A central theme of the course is that **building a model is often the easiest part of machine learning**. True impact requires an end-to-end process:

> It is easy to run an algorithm on downloaded data.  
> It is hard to identify the right problem, collect appropriate data, select features, choose methods, evaluate properly, interpret results, and drive adoption.

### Key Stages of ML That Matter
- **Problem identification**
- **Data collection and preprocessing**
- **Feature selection and engineering**
- **Algorithm selection**
- **Evaluation and validation**
- **Interpretation and communication**
- **Deployment and user adoption**

The course emphasizes a **holistic, process-driven approach**, not just algorithm mechanics.

## 2. What is Machine Learning?

### Definition
Arthur Samuel (1959):
> Machine learning is the field of study that gives computers the ability to learn without being explicitly programmed.

### Learning in ML
- **Task-based learning**: Building expertise at a specific task.
- **Generalization**: Transferring learned patterns to new, unseen data.

### Why Use Machine Learning?

ML is appropriate when:

- Automation provides benefit (faster, cheaper, better).
- Rules are:
  - Too complex to specify manually.
  - Unknown or poorly understood.
- Traditional software approaches are infeasible.

---

## 3. What is a Model?

A **model** is:

> A useful approximation of a non-random phenomenon.

Mathematically:

\[
y = f(x) + \varepsilon
\]

Where:
- \(x\): Input variables (features)
- \(y\): Output variable (target)
- \(\varepsilon\): Irreducible error (noise)

### Interpretation
- Models **compress knowledge** into parameters.
- All models are wrong; some are useful.
- A model must be:
  - Non-random
  - Useful
  - An approximation

## 5. Supervised vs. Unsupervised Learning

### Supervised Learning
- Have features \(X\) and targets \(Y\)
- Learn mapping \(f: X \rightarrow Y\)

Types:
- **Regression** → Numeric output
- **Classification** → Categorical output

### Unsupervised Learning
- Only features \(X\)
- No labeled target
- Goal: Discover structure (e.g., clustering)

### Important Insight
Some problems can be formulated as either regression or classification depending on business requirements.

---

## 6. Heuristics vs. Machine Learning

### Heuristics
- Rule-based systems
- Hard-coded decision logic
- Example: Recommend most popular item

Benefits:
- Easy to build
- Low computational cost
- High interpretability

### Machine Learning
- Learns patterns from data
- Adaptive (can retrain)
- Handles complex relationships

### Best Practice
Always begin with:
1. **Heuristic baseline**
2. **Simple ML baseline**
3. Then increase complexity if justified

---

## 7. Algorithm Selection

### No Free Lunch Theorem
No single algorithm is best for all problems.

### Three Key Criteria

1. **Performance**
2. **Interpretability**
3. **Computational cost**

### Occam’s Razor
> All else equal, choose the simpler model.

Simple models:
- Easier to maintain
- More robust to drift
- Often generalize better
- May perform as well as complex models

Industry often prioritizes:
- Practicality
- Maintainability
- Interpretability

## 8. Model Evaluation

### Train-Test Split

Purpose: Estimate generalization performance.

Typical split:
- 80–90% Training
- 10–20% Test

**Never tune models on the test set.**

---

## 9. Sampling

### Why Sample?
- Limited access to full population
- Computational constraints

### Types of Sampling

#### Non-probability Sampling
- Convenience sampling
- Snowball sampling
- Judgment sampling
- Quota sampling

Risk:
- Bias
- Poor generalization

#### Random Sampling
- Simple random sampling
- Stratified sampling
- Weighted sampling

Stratified sampling is crucial for:
- Class imbalance

---

## 10. Data Leakage

**Data leakage occurs when test information influences training.**

Common causes:
- Feature selection before splitting
- Scaling before splitting
- Imputation before splitting
- Duplicate records across splits
- Random splitting of time series
- Group leakage (e.g., same patient in train/test)

### Rule:
> Split first. Preprocess second.

---

## 11. Validation & Cross-Validation

### Three-Way Split
- Training
- Validation
- Test

### K-Fold Cross-Validation
- Divide into \(K\) folds
- Train on \(K-1\), validate on remaining
- Average validation error

Benefits:
- Better generalization estimate
- Efficient use of small datasets

Variants:
- ShuffleSplit
- Leave-One-Out (LOOCV)

After CV:
- Final evaluation must still use test set.

## 12. Bias–Variance Tradeoff

Total error consists of:

\[
\text{Error} = \text{Bias}^2 + \text{Variance} + \text{Irreducible Error}
\]

### Bias
- Error from overly simple assumptions
- Underfitting

### Variance
- Sensitivity to training data noise
- Overfitting

### Optimal Model
Found at balance point between bias and variance.

### Overfitting Pattern
- Training performance ↑
- Validation performance peaks then ↓
- Divergence indicates overfitting

Model complexity influenced by:
- Algorithm choice
- Number of features
- Hyperparameters
- Dataset size

## 13. Metrics: Outcomes vs. Outputs

### Outcome
- Business goal
- Measured in impact (e.g., cost reduction)

### Output
- Model performance metric
- Technical measure

Example:

| Problem | Outcome | Output |
|----------|----------|----------|
| Turbulence prediction | Fewer safety incidents | AUROC |
| Power demand forecasting | Lower cost per MWh | MSE |

**Define outcome first. Then choose metric.**

## 14. Regression Metrics

### Mean Squared Error (MSE)

\[
MSE = \frac{1}{n}\sum (y_i - \hat{y}_i)^2
\]

- Penalizes large errors heavily
- Scale dependent
- Differentiable

### Mean Absolute Error (MAE)

\[
MAE = \frac{1}{n}\sum |y_i - \hat{y}_i|
\]

- More robust to outliers
- Easier interpretation

### Mean Absolute Percentage Error (MAPE)

\[
MAPE = \frac{100}{n}\sum \left|\frac{y_i - \hat{y}_i}{y_i}\right|
\]

- Interpretable
- Problematic when \(y\) near zero

### R² (Coefficient of Determination)

\[
R^2 = \frac{\text{Explained Variance}}{\text{Total Variance}}
\]

Ranges:
- 0 to 1

### Adjusted R²
Penalizes additional features to account for overfitting.

Metric choice depends on:
- Business objective

# Core Takeaways

- ML is a **process**, not just an algorithm.
- Always establish a **baseline**.
- Prefer **simpler models** when adequate.

- Use **cross-validation** properly.

- Align model metrics with **business outcomes**.
- Evaluate models in context, not in isolation.
